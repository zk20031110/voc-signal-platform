# 界面说明

界面上不再放解释性文案，操作方式和每块区域的含义都收在这份文档里。

---

## 一、整体结构

顶部一条状态栏，下面是四个页签。

顶部状态栏从左到右：

1. 品牌名与产品定位
2. 当前使用的模型（如 deepseek-flash）
3. Agent1 输入形态切换：逐条调用 / 批量调用
4. 「采集并分析」按钮：整条流水线的启动入口
5. 三段指示灯：01 采集标注 / 02 风险归因 / 03 洞察建议，每段后面显示该阶段耗时

页签：分析工作台、评测看板、标签体系、人工复核。

---

## 二、分析工作台

三栏布局，从左到右是数据的流向。

### 左栏 · 反馈源

放的是未加工的多渠道原始语料：商品评价、客服对话、退款说明。每条都有编号（F001、F002…），编号是后面证据下钻用的锚点。

上方三个卡片是批次切换器，切换批次会清空当前结论，需要重新点「采集并分析」。

### 中栏 · 协作流水线

三个 Agent 卡片，代表流水线的三次模型调用。卡片状态有四种：待机、运行中（带进度条）、完成、失败。

**Agent1 输入形态切换**（也在顶部状态栏）：

- 逐条调用（默认）：一条一次调用。一条失败只影响一条，鲁棒性最好。
- 批量调用：一次吃一批（默认每批 10 条），调用次数降一个量级。输出条数或编号与输入对不齐时，这一批会自动回退成逐条重跑，不会静默丢反馈。

卡片完成后会显示实际发生的模型调用次数，以及批量回退的批数。

### 右栏 · 结论与证据

自上而下四块：

1. **历史信号库 · 过去 7 天**：Agent2 判断「这是偶发噪声还是扩散趋势」的基线数据，含每个标签的总量、负面量、趋势。
2. **风险分组**：聚合层按「风险等级 + 主标签」把逐条风险归并后的结果。组内取最严重的等级，合并全部证据。
3. **洞察报告**：只对「高」和「观察」两级生成，常规项不生成报告，避免打扰。
4. **HUMAN-IN-THE-LOOP 提示**：批次里含高优先级信号时出现，提醒这些信号需人工复核后才对外推送。

**证据下钻**：点报告里的语料编号（F001 这类），左栏会自动滚动到那条原始反馈并高亮。

## 三、评测看板

点「运行评测」跑的是 `eval/testset-holdout.json`——30 条独立留出集，与 Prompt 里写的示例不重叠，所以指标可以对外引用。口径定义见 `eval/metrics.md`。

跑完输出六项指标，分两层：

| 层级 | 指标 | 说明 |
| --- | --- | --- |
| 模型层 | 标签命中率 | 预期标签是否全部命中 |
| 模型层 | 情感判断 F1 | 负面类别的精确率与召回率调和平均 |
| 模型层 | 新信号召回率 | 该标新信号的用例里，实际标出来的比例 |
| 业务层 | 高风险召回率 | 该判「高」的用例里，实际判出来的比例。漏报代价最大 |
| 业务层 | 误报率 | 「常规」用例被升级成高或观察的比例。只有高和观察会打扰商家 |
| 综合 | 用例通过率 | 标签、情感、新信号、风险四项全对才算通过 |

下方两个面板：**用例逐条判定**（每条用例的期望值 vs 实际值）和 **Badcase 归因**（五类：检索 / 模型 / Prompt / 数据 / 产品设计，可手动轮换归类）。

注意：同一份 Prompt 连跑多次，通过率会上下浮动，这是模型随机性，不是回归。判断改动好坏要看多组，不要只看一次。

## 四、标签体系演化

**候选新标签**：Agent1 在标注时发现「现有 8 类标签表达不了的具体概念」时会标记为新信号，并在这里汇总，含出现次数与原文。

**已生效标签**：预设 8 类 + 人工确认过的自定义标签。点「确认为正式标签」后，这个标签会写入 `data/labels.json`，并在下次标注时注入 Agent1 的 Prompt，Agent1 会直接使用它。

---

## 五、人工复核

**待复核**：Agent2 标记需要人工确认的高风险分组，卡片直接给出复核需要的全部材料——风险依据、归因分析、证据原文，不用切回工作台翻语料。

**复核历史**：已判定的记录。点「确认真实风险」或「判定为误报」后，结论会写入 `data/reviews.json` 并回流到 Agent2 的 Prompt：确认过的同类保持敏感，判为误报的同类不再升级。

## 六、常见操作

| 想做什么 | 怎么做 |
| --- | --- |
| 跑一次完整分析 | 选批次 → 点「采集并分析」，9 条反馈约 35~50 秒 |
| 换批次 | 点左栏的批次卡片，然后重新点「采集并分析」 |
| 降低成本 | 顶部把 Agent1 切到「批量调用」，30 条样本的标注调用从 30 次降到 3 次 |
| 看某条结论的原始证据 | 点右侧报告里的语料编号 |
| 验证一次改动有没有把别的用例改坏 | 切到评测看板点「运行评测」，跑留出集 |
| 让 Agent1 学会一个新标签 | 标签体系页确认候选标签，再回工作台重跑 |
| 校准 Agent2 的敏感度 | 人工复核页判定一条，再回工作台重跑 |

---

## 七、启动方式

```bash
python server.py          # 启动后打开 http://localhost:8000
```

端口被占用时换一个：`python server.py 8010`。

页面上跑分析需要项目根目录的 `.env` 里配置 `DEEPSEEK_API_KEY`；没配也能打开页面，只是点了分析会报错。
