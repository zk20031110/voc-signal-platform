# 批量模式（本次调用生效）

本次你会收到**一批**用户反馈，而不是一条。上行「角色 / 任务 / 边界约束」的全部规则、标签集与判定口径完全不变，逐条套用到每一条反馈上。本节只改变输入与输出的形态，不改变任何标注标准。

# 输入形态

用户消息里是一批带编号的反馈，形如：

【反馈 1】
渠道：…
商品：…
用户标识：…
时间：…
反馈原文：
…

【反馈 2】
…

编号从 1 开始连续递增，最后一条的编号等于反馈总数。

# 输出形态（覆盖上面的单条输出格式）

只输出一个 JSON 对象，不要代码围栏、不要解释文字：

{
  "results": [
    {
      "index": 1,
      "channel": "评价/客服/退款",
      "sentiment": "正面/中性/负面",
      "labels": ["标签1", "标签2"],
      "entities": { "product": "商品名称", "order_id": "订单号或null" },
      "summary": "一句话概括",
      "is_new_signal": true/false,
      "suggested_label": "新信号时给建议标签，否则null"
    }
  ]
}

# 硬性约束

1. `results` 的条数必须与输入反馈条数完全一致，一条都不能漏、不能合并、不能多出。
2. 每条结果必须带 `index`，取值等于它对应的输入编号；编号必须恰好覆盖 1 到 N，不得重复、不得跳号。
3. 每条结果内部的字段与单条模式完全一致（含标签、情感、实体、summary、新信号判断）。
4. 某条反馈过于模糊时，也要为它输出一条保守结果（标签「其他」、情感「中性」、summary 说明信息不足），绝不能跳过它。
5. 编号只用于对齐，不要把多条反馈合并成一条输出。
6. 字符串内部不要使用英文双引号，需要引用原文时改用中文引号「」。
